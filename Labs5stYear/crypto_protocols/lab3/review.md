# Review/Tests: Diffie–Hellman (Lab3)

Сценарии проверки корректной и некорректной работы реализации протокола Диффи — Хеллмана.

## Пререквизиты
- Сервер запущен: `python3 lab3/server.py`
- Клиент готов к использованию: `python3 lab3/client.py`
- Для ручных команд можно подключиться через `telnet localhost 12345` или `nc localhost 12345`

## 1) Базовый успешный обмен ключами
1. Запустить сервер, дождаться сообщения о порте.
2. На клиенте выполнить `python3 lab3/client.py --verbose`.
3. Ожидание: клиент загружает группу RFC 3526 (по умолчанию group14), выводит одинаковые SHA-256 значения с сервером и сообщение `Shared secret match confirmed.`
4. На сервере команда `STATUS` показывает последний открытый ключ клиента, hex общего секрета и его хэш.

## 2) Загрузка предустановленных групп RFC 3526
1. Подключиться к серверу вручную (telnet).
2. Выполнить `RFC group15` — сервер должен подтвердить загрузку и пересоздать свой открытый ключ.
3. Снова вызвать `PARAMS`; биты параметров ≈3072.
4. Запустить клиента с флагом `--group group15`; ожидается успешный обмен и совпадение SHA-256.

## 3) Генерация собственных параметров
1. Через telnet отправить `GENERATE 512`. Сервер должен сгенерировать безопасное простое и сообщить об успехе.
2. Проверить `PARAMS JSON`: поле `name` имеет вид `safe-prime-512`.
3. Клиент с опцией `--generate 512` должен успешно завершить обмен; хэш совпадает.

## 4) Некорректный открытый ключ (нарушение диапазона)
1. Получить параметры через `PARAMS`, взять `P`.
2. Отправить `PUB 1` или `PUB (P-1)`.
3. Ожидание: сервер отвечает `ERROR: Peer public key not in subgroup`; секрет не формируется, `SECRET` сообщает об отсутствии данных.

## 5) Некорректный открытый ключ (не принадлежит подгруппе)
1. Сгенерировать случайное число меньше `P`, но не удовлетворящее `y^q mod p = 1` (например, выбрать `rand % (P-2) + 2` и проверять условие).
2. Отправить его через `PUB`.
3. Сервер должен вернуть ту же ошибку про подгруппу. Проверить, что предыдущее корректное значение всё ещё позволяет получить секрет.

## 6) Несовпадение общего секрета (манипуляция клиентом)
1. Запустить клиента с флагом `--private`, выбрав корректное значение `x_a`.
2. Выполнить обмен и сохранить ответ сервера.
3. Повторно отправить команду `PUB`, но использовать модифицированный (например, инкрементированный) открытый ключ клиента.
4. На стороне клиента рассчитать секрет для исходного `Y_b`; ожидается Warning о несовпадении SHA-256.

## 7) Проверка ротации ключей сервера
1. После успешного обмена запросить `STATUS` и запомнить `Last server public`.
2. Отправить ещё один корректный `PUB`.
3. Новый вызов `STATUS` показывает иной `Server public`; предыдущий секрет остаётся доступным в блоке `Last secret hex`.

## 8) Обработка ошибочных команд
- `RFC unknown` → сервер сообщает об ошибке «Unknown RFC3526 group».
- `GENERATE 128` → ответ «Bits must be >= 256».
- `PARAMS YAML` → сервер вернёт параметры в десятичном виде, подтверждая, что поддерживаются только `JSON` и `HEX`.
- Пустая строка или неизвестная команда → «Unknown command. Type HELP.»

## 9) Завершение сеанса и повторное подключение
1. После команды `QUIT` клиент должен закрыть соединение без ошибок.
2. При новом подключении сервер создаёт свежую сессию с новым серверным открытым ключом.

## 10) Проверка отказоустойчивости
- Несколько клиентов одновременно: параллельно запустить два экземпляра `client.py`; оба должны успешно завершить обмен, у каждого — собственные секреты.
- При резком обрыве соединения (Ctrl+C на клиенте) сервер продолжает обслуживать другие подключения, а `STATUS` нового клиента не содержит старого секрета.
