# Lab3 — Diffie-Hellman (RFC 2631)

Лабораторная работа реализует взаимный обмен ключами по протоколу Диффи — Хеллмана в терминах RFC 2631. Реализация доводится до момента вычисления общего секрета `ZZ = g^(x_b * x_a) mod p`. Код повторяет стиль предыдущих лабораторных работ: есть TCP-сервер с текстовым интерфейсом и вспомогательные утилиты на Python без внешних зависимостей.

## Состав проекта

- `dh.py` — ядро протокола: генерация параметров, проверка простоты (Miller–Rabin), поиск генератора, вычисление открытых/секретных ключей и простая KDF на SHA-256.
- `rfc3526.py` — предустановленные доменные параметры (1536, 2048 и 3072 бит) из RFC 3526; могут загружаться командой `RFC`.
- `server.py` — TCP-сервер, поддерживающий команды для просмотра/генерации параметров, проверки открытых ключей и расчёта общего секрета.
- `client.py` — автономный клиент: получает параметры от сервера, генерирует приватный ключ, отправляет `PUB` и сверяет общий секрет.

## Алгоритмы

### 1. Получение параметров (p, q, g)

1. **Предустановленные группы** — из RFC 3526, секции 2–4. Загрузка выполняется командой `RFC <group>` (`group5`, `group14`, `group15`). Для каждой группы p — безопасное простое число (safe prime), g = 2, q = (p-1)/2.
2. **Генерация собственных параметров** — командой `GENERATE <bits>`:
   - `generate_safe_prime(bits)` выбирает случайное нечётное число длиной `bits-1`, проверяет его на простоту (`is_probable_prime`) — это будущий q.
   - `p = 2*q + 1`; снова проверяется простота.
   - `find_generator` ищет генератор подгруппы порядка q по схеме RFC 2631: выбирается случайное `h`, вычисляется `g = h^{(p-1)/q} mod p`, дополнительно проверяется `g ∉ {1, p-1}` и `g^q mod p = 1`.

### 2. Проверка простоты

`is_probable_prime(n, rounds=64)` — стандартный тест Миллера — Рабина: сначала отбрасываются делители из набора малых простых, затем выполняются 64 случайных раунда. Такой режим подходит для чисел «сотен бит», как требовалось в задании.

### 3. Проверка открытого ключа

`validate_public_key(y, params)` реализует пункт 2.1.5 RFC 2631:
- `1 < y < p - 1`;
- `y^q mod p == 1` — попадание в подгруппу порядка q.

### 4. Генерация общего секрета

`derive_shared_secret(peer_public, private_key, params)` вычисляет `pow(peer_public, private_key, p)`. Сервер хранит последний результат в hex (`SHARED_SECRET_HEX`) и его хэш SHA-256 (`SHA256`) для сверки с клиентом. После вычисления сервер автоматически регенерирует собственную пару ключей — эпизодический режим (ephemeral DH).

## Структура сообщений

TCP-сервер (порт `12345`) принимает текстовые команды, аналогично предыдущим лабораторным: 
- `PARAMS [JSON|HEX]` — параметры домена и текущий открытый ключ сервера (формат JSON удобен клиенту).
- `RFC <group>` — загрузить одну из групп RFC 3526.
- `GENERATE <bits>` — сгенерировать новое безопасное простое и генератор.
- `PUB <value>` — отправить открытый ключ клиента (десятичный или `0x`-hex). В ответ — `SHARED_SECRET_HEX` и `SHA256`.
- `SECRET`, `KDF`, `STATUS`, `RESET`, `HELP`, `QUIT` — служебные команды.

Клиент (`client.py`) автоматизирует сценарий: по желанию задаёт группу/длину, получает `PARAMS JSON`, валидирует открытый ключ сервера, генерирует приватный ключ (или использует `--private`), отправляет `PUB` и проверяет совпадение SHA-256 общего секрета.

## Упрощения по сравнению с RFC 2631

- Рассматривается только safe-prime подгруппа порядка q = (p-1)/2; инфраструктура сертификатов, идентификация и ASN.1-структуры RFC опущены.
- KDF сведена к `SHA-256(ZZ)` без использования `OtherInfo` из стандарта.
- Общий секрет не используется дальше (не выводится симметричный ключ, не выполняется IKE). Цель — продемонстрировать корректное получение `ZZ`.

## Пример использования

1. Запустить сервер:
```bash
python3 lab3/server.py
```
2. Выполнить клиент (по умолчанию группа 14):
```bash
python3 lab3/client.py --host localhost --port 12345 --verbose
```
3. Сгенерировать параметры на 512 бит (демо):
```bash
python3 lab3/client.py --generate 512 --verbose
```

Клиент выводит открытые ключи обеих сторон, общий секрет и его SHA-256 со сверкой совпадения.

## Дополнительно

- Допускаются десятичные и шестнадцатеричные представления (`PUB 0x...`, `PARAMS HEX`).
- Сервер хранит последний секрет в памяти для учебных команд `SECRET` и `KDF`; в реальной системе секрет нужно уничтожать сразу после использования.
