# Review/Tests: Протокол связной метки (Lab5)

Ниже — сценарии проверки корректной работы реализации. Все команды выполняются из корня репозитория `crypto_protocols/`.

## Пререквизиты
- Доступен Python 3.
- В отдельном терминале запустить сервер Трента:
  ```bash
  python3 lab5/server.py --host 127.0.0.1 --port 13000 --verbose
  ```

## 1) Базовая постановка метки (один клиент)
1. Выполнить:
   ```bash
   python3 lab5/client.py stamp --host 127.0.0.1 --port 13000 --name Alice --text "hello"
   ```
2. Ожидание: клиент выводит объект `STAMPED` с полями `token`, `signature`, `pubkey`.
3. Сохранить весь JSON в файл `token1.json` (для последующей проверки).

## 2) Создание цепочки (несколько клиентов)
1. В новом терминале выполнить:
   ```bash
   python3 lab5/client.py stamp --host 127.0.0.1 --port 13000 --name Bob --text "world"
   ```
2. Ожидание: в ответе будет `token.n = 2`. На сервере видно журнал `STAMP n=2 for Bob`.
3. Для контроля получить токен `n=1` и `n=2` напрямую:
   ```bash
   python3 lab5/client.py get --n 1
   python3 lab5/client.py get --n 2
   ```
   Убедиться, что у токена `n=2` поле `prev_summary.n == 1`, а `link_hash` отличается от `n=1`.

## 3) «Сосед» (кто пришёл после меня)
1. Для `n=1` запросить соседа:
   ```bash
   python3 lab5/client.py neighbor --n 1
   ```
2. Ожидание: `next_requester` = `Bob` (идентификатор отправителя токена `n=2`).

## 4) Проверка подписи и целостности токена
1. Проверить сохранённый из п.1 токен:
   ```bash
   python3 lab5/client.py verify --token token1.json
   ```
2. Ожидание: `{"valid": true}`.
3. Открыть `token1.json`, изменить пару символов в `token.doc_hash` и повторить команду — ожидание: `valid=false` и сообщение о причине.

## 5) Доказательство порядка (sandwich)
1. Имея токены `n=1` (Alice) и `n=2` (Bob), показать, что документ Alice помечен раньше Bob:
   - Подписи обоих токенов валидны (`verify`).
   - В `token(n=2)` присутствует `prev_summary.n = 1`, а сервер сообщает `neighbor(n=1) = Bob`.
   - Следовательно, метка времени Alice находится перед меткой Bob, что исключает перенос метки Alice на более позднее время без нарушения подписи/цепочки.

## 6) Неверный публичный ключ
1. В `token1.json` заменить поле `pubkey.n` на случайное число и запустить `verify`.
2. Ожидание: `valid=false`.

## 7) Монотонность номеров
1. Несколько раз выполнить команду `stamp` с разными именами/текстами.
2. Ожидание: `n` возрастает на 1 каждый раз, перескоков и повторов нет.

## Завершение
- Сервер останавливается `Ctrl+C`.
- Для быстрой проверки синтаксиса: `python3 -m compileall lab5`.
