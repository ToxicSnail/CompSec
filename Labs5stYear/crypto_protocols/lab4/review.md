# Review/Tests: Oakley Main Mode (Lab4)

Ниже перечислены сценарии для проверки корректной и некорректной работы реализации режима Main Mode с PSK. Во всех примерах предполагается, что репозиторий находится в корне (`crypto_protocols/`).

## Пререквизиты
- Python 3 доступен в PATH.
- В отдельном терминале запускаем респондера:
  ```bash
  python3 lab4/server.py --host 127.0.0.1 --port 12000 --psk lab4-shared-secret --verbose
  ```
- Для ручного воспроизведения сообщений удобно использовать `nc -v localhost 12000` (или `socat`/`telnet`).

## 1) Базовый успешный обмен
1. В новом терминале выполнить `python3 lab4/client.py --host 127.0.0.1 --port 12000 --verbose`.
2. Ожидание: клиент выводит `Handshake completed successfully`, общий секрет и четыре значения `SKEYID*`.
3. Сервер в консоли журналирует `MSG1/MSG2/MSG3/MSG4` и отправляет `RESULT` с теми же ключами.

## 2) Неверный предварительно разделяемый ключ
1. Остановить клиента (сервер можно не трогать).
2. Выполнить `python3 lab4/client.py --port 12000 --psk wrong-secret`.
3. Ожидание: клиент завершится с сообщением `Handshake failed: Server reported error: HASH_I mismatch…`, сервер выдаст JSON `{ "type": "ERROR" }` и закроет соединение.

## 3) Проверка другой DH-группы
1. Перезапустить сервер с `--group 1`.
2. Запустить клиента `python3 lab4/client.py --group 1 --verbose`.
3. Ожидание: обмен проходит успешно, публичные ключи имеют длину ≈768 бит, в SA указана группа `MODP-768`.

## 4) Сравнение вычисленных ключей (debug блок)
1. Запустить клиента с флагами `--verbose --dump`.
2. Убедиться, что в `MSG4` поле `debug` содержит значения `SKEYID…`, `Ni`, `Nr`, `g_xy`.
3. Сверить с собственным выводом клиента — все значения должны совпасть (формат hex в нижнем регистре).

## 5) Обновление Cookies и не повторяется ли `g^xy`
1. Дважды запустить клиента последовательно (оставив сервер работать).
2. Сравнить `cookie_r` и `g^xy` из двух запусков: значения должны отличаться, что подтверждает ротацию приватных ключей и защиту от повторов.

## 6) Реакция на некорректный порядок сообщений
1. Подключиться к серверу через `nc localhost 12000`.
2. Скопировать JSON `MSG3` из успешного запуска, отправить его первым.
3. Ожидание: сервер вернёт `{ "type": "ERROR", "error": "Expected MSG1 from initiator" }`.

## 7) Подмена HASH_I
1. Выполнить `python3 lab4/client.py --dump --psk lab4-shared-secret` и сохранить JSON `MSG3`.
2. Отправить сохранённый `MSG3`, но изменив пару символов в `HASH_I`.
3. Ожидание: сервер возвращает `ERROR`, клиент (если использовать модифицированный скрипт) видит сообщение о провале.

## 8) Настройка идентификаторов
1. Запустить сервер с `--identity 10.0.0.1`.
2. Клиент — с `--identity 10.0.0.2`.
3. Ожидание: `IDii` и `IDir` в сообщениях используют новые адреса; хеши остаются корректными.

## Завершение
- `Ctrl+C` на сервере корректно останавливает демон.
- Для быстрой проверки синтаксиса: `python3 -m compileall lab4`.
